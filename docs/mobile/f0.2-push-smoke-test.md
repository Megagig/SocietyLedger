# F0.2 manual smoke test (curl)

Run against a local dev server (`pnpm -F @societyledger/api dev`) with the demo association seeded (`pnpm -F @societyledger/api seed:demo`). Replace `$TOKEN` with a real login token.

```bash
# 1. Login (demo member) — no X-Tenant header needed, /auth/login is tenant-optional
curl -s -X POST http://localhost:4000/api/auth/login \
  -H "Content-Type: application/json" -H "X-Tenant: demo" \
  -d '{"email":"member@demo.com","password":"password123"}'
# -> copy data.token into $TOKEN and data.user.id into $USER_ID below

# 2. Register a device (upsert by token; re-run to confirm the upsert path)
curl -s -X POST http://localhost:4000/api/devices/register \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"expoPushToken":"ExponentPushToken[REPLACE_WITH_A_REAL_TOKEN]","platform":"android","deviceName":"Test","appVersion":"1.0.0"}'

# 3. As an officer (admin@demo.com), dispatch a notification at that user — exercises
#    dispatchNotification's new push step end-to-end (push failure, e.g. an invalid
#    token, must still return 201 here — see push.service.ts's fire-and-forget guarantee)
curl -s -X POST http://localhost:4000/api/auth/login \
  -H "Content-Type: application/json" -H "X-Tenant: demo" \
  -d '{"email":"admin@demo.com","password":"password123"}'
# -> copy data.token into $ADMIN_TOKEN

curl -s -X POST http://localhost:4000/api/notifications \
  -H "Content-Type: application/json" -H "Authorization: Bearer $ADMIN_TOKEN" -H "X-Tenant: demo" \
  -d '{"title":"Smoke test","message":"Testing push","type":"system","userId":'"$USER_ID"'}'
# -> expect 201 { data: { inAppCreated: true, ... } } regardless of whether the push
#    itself succeeds — check the server log for "[push.service] send error" if the
#    token isn't a real device.

# 4. Unregister
curl -s -X POST http://localhost:4000/api/devices/unregister \
  -H "Content-Type: application/json" -H "Authorization: Bearer $TOKEN" \
  -d '{"expoPushToken":"ExponentPushToken[REPLACE_WITH_A_REAL_TOKEN]"}'
```

Confirmed working end-to-end on 2026-10-19 (local dev, demo association) with a syntactically-valid-but-fake Expo token: Expo's real API correctly rejected it with `DeviceNotRegistered`, `push.service.ts` disabled the token row in response, and the originating `POST /api/notifications` request still returned `201` — the request was never affected by the push failure.
