SocietyLedger has a full SMS module — a dashboard, Quick Send, campaigns, templates and history — reachable from <MenuPath items={["Communication", "SMS Dashboard"]} />. The dashboard itself loads correctly.

## How it works

<Callout type="danger" title="Quick Send currently fails every time">
Opening <MenuPath items={["Communication", "Quick Send SMS"]} />, picking a recipient and a message, and selecting **Send Message** always fails with a validation error. The page sends each recipient as `{ type, value }`, but the API expects a plain phone number or member ID string — so the request is rejected before anything is sent. This isn't occasional; every attempt fails the same way, confirmed directly against the API. It's logged for a fix in a later phase; there's currently no way to send an SMS from this screen.
</Callout>

<Screenshot src="/images/communication/sms-dashboard-1.webp" alt="SMS Dashboard showing 0 credits remaining, 0 messages sent, and Quick Actions for Send, Create Campaign and View History" />

The dashboard shows your SMS credit balance, messages sent/delivered/failed, and active campaigns — all of which read correctly.

## Why it matters

Even if the data-format problem above is fixed, sending still needs **SMS credits** — see [Buying SMS credits](/docs/communication/buying-sms-credits), which has its own problems — and a live connection to the SMS provider (Termii), which isn't configured in this environment. Budget for both before relying on SMS.
